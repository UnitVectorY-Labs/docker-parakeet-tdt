# docker-parakeet-tdt

Purpose-built NVIDIA Parakeet TDT 0.6B v3 CUDA transcription server, using
unmodified [NVIDIA/NeMo-Speech.cpp](https://github.com/NVIDIA/NeMo-Speech.cpp)
pinned to `caa3f47c7c75fa2e9e6340272ebad57c1647dd44`. Only ASR, its CLI and HTTP
server are built; no Python, NeMo toolkit, Torch, TTS, diarization, NMT, gRPC,
microphone capture, or API wrapper. The runtime is Google Distroless
`cc-debian13:nonroot`, UID/GID 1000, with the native binary and required ELF/CUDA
libraries copied from a CUDA 13.0.2 Ubuntu 24.04 builder. No shell, compiler,
package manager, CUDA toolkit, driver, or model weights are shipped.

## Model and run

Download the **official** Q8_0 GGUF, not the original NeMo checkpoint:

```sh
hf download nvidia/parakeet-tdt-0.6b-v3 parakeet-tdt-0.6b-v3.q8_0.gguf \
  --local-dir /home/jared/.cache/asr-models/parakeet-tdt-0.6b-v3
```

The 713,975,456-byte model has SHA256
`e3880d0aaaaf2c308ea2c35016b2b895c423eb3fda924c1b463d1c19b7f4d32e`.
It is [CC-BY-4.0](https://huggingface.co/nvidia/parakeet-tdt-0.6b-v3), by NVIDIA;
retain attribution when distributing it. Weights stay external, readable by
UID/GID 1000, and mount read-only. No weights are downloaded during the build.

```sh
docker run --rm --gpus all --user 1000:1000 \
  --memory 8g --memory-swap 8g \
  -p 127.0.0.1:8080:8080 \
  -v /home/jared/.cache/asr-models/parakeet-tdt-0.6b-v3:/model:ro \
  ghcr.io/unitvectory-labs/docker-parakeet-tdt:current
```

Requires NVIDIA Container Toolkit and a CUDA 13-compatible host driver. CI
builds native Linux ARM64 for DGX Spark/GB10 (`sm_121`) and native AMD64 for
`sm_80/86/89/90/100/120`; no emulation or build-host GPU autodetection. Other
targets need a rebuild with `--build-arg CUDA_ARCHITECTURES=...`.

Entrypoint: `/opt/nemo/bin/nemo-speech`. Default command:

```sh
nemo-speech serve --asr-model /model/parakeet-tdt-0.6b-v3.q8_0.gguf \
  --gpu 0 --host 0.0.0.0 --port 8080 --no-ui --threads 1 --max-upload-mb 32
```

Override the complete argument list after the image name. One worker bounds
request processing; 32 MiB bounds upload size, not GPU memory or audio duration.
Use short recordings initially. The model runtime may allocate much more than
the weight size, particularly on long recordings. Docker limits do not reliably
bound GPU/unified allocations on GB10; measure physical RAM with `free` or
`/proc/meminfo`, and do not infer safe LLM co-loading from the cgroup cap.

No cache mount is required for a local GGUF. Writable `/tmp` is needed (provide
`--tmpfs /tmp:uid=1000,gid=1000` for `--read-only`). PID 1 is the upstream binary,
without a shell wrapper. The service is unauthenticated: bind to loopback for
standalone use or keep it on a private Docker network behind a trusted proxy.

## API and timestamps

`GET /health` and `GET /ready` return 200 when ready, otherwise 503 (connection
refused before listening). Docker's exec-form health check uses the native
`nemo-speech health` command; no curl/Python health-check dependency.

`POST /v1/audio/transcriptions` accepts multipart `file` (WAV), `model`, and
`response_format`. `model` is accepted for compatibility; the server always
uses its single loaded checkpoint. Use mono 16 kHz PCM WAV for the smoke test.
Convert other formats on the client, e.g.:

```sh
ffmpeg -i recording.mp3 -ac 1 -ar 16000 -c:a pcm_s16le recording.wav
curl --fail-with-body \
  -F model=parakeet-tdt-0.6b-v3 -F file=@recording.wav \
  -F response_format=verbose_json \
  http://127.0.0.1:8080/v1/audio/transcriptions
```

`verbose_json` returns `text`, `task`, `language`, `duration` (seconds), and
`words: [{"word": "...", "start": 0.0, "end": 0.3, "confidence": ...}]`.
Word times are seconds, generated by the upstream model/runtime. There is no
need for `timestamp_granularities[]`; this upstream subset selects word times
with `verbose_json`, not OpenAI's complete parameter/segment schema. Plain
`json`, `text`, `srt`, and `vtt` are also supported. No diarizer is included.

### Minimal end-to-end test

With the server running, a short WAV **containing speech**, and Python 3 on
the client:

```sh
python3 tests/transcribe.py recording.wav --base-url http://127.0.0.1:8080
```

The test sends an actual multipart upload, requires nonempty text and words,
checks finite, ordered word timestamps within the recording duration, and
prints the full timestamped JSON. It fails on HTTP errors or missing timestamps.
For llama-swap use `--base-url https://llm.unitvectory-labs.net` and the same
model ID. A cold request starts the model automatically.

## llama-swap

```yaml
models:
  parakeet-tdt-0.6b-v3:
    proxy: "http://${MODEL_ID}:8080"
    checkEndpoint: /ready
    cmd: |
      docker run --rm --gpus all --memory 8g --memory-swap 8g \
        --network llama-backend --name ${MODEL_ID} \
        -v /home/jared/.cache/asr-models/parakeet-tdt-0.6b-v3:/model:ro \
        ghcr.io/unitvectory-labs/docker-parakeet-tdt:current
    cmdStop: docker stop ${MODEL_ID}
    concurrencyLimit: 1
    ttl: 3600
```

No host port is published in this mode. The deployment repository owns its
matrix policy; initially run Parakeet alone until physical memory is measured.
llama-swap already routes multipart `/v1/audio/transcriptions` by `model`.
Do not broaden an external proxy's endpoint allowlist implicitly.

## Builds and validation

Follows [docker-breeze-tts](https://github.com/UnitVectorY-Labs/docker-breeze-tts)
conventions: multi-stage Distroless, non-root, external weights, SHA-pinned
upstream and Actions, native `ubuntu-24.04-arm`/`ubuntu-24.04` runners, PR builds
without publication, push/manual/weekly Saturday 02:00 UTC builds, GHCR OCI
labels, and weekly Docker/Actions Dependabot updates. No Python requirements
or Breeze-specific runtime policies are needed.

Tags: `current`, `current-arm64`, `current-amd64`, first-success `sha-<full SHA>`,
unique `sha-<full SHA>-run-<run ID>-<attempt>` and matching architecture run tags.
Use a manifest digest for immutable deployment. GHCR package visibility may
need to be made public separately by an organization admin.

```sh
docker build --build-arg CUDA_ARCHITECTURES=121 -t parakeet-tdt:local .
gh workflow run docker-build.yml --repo UnitVectorY-Labs/docker-parakeet-tdt
```

Every build checks the packaged ELF/CUDA libraries, absence of weights/driver,
non-root home ownership, notices, and excluded tooling. It executes CLI/server/
health help in the actual shell-free runtime. A **test-stage-only** CUDA driver
stub permits these checks on GPU-less CI; the final image never contains it.
These checks do **not** establish CUDA inference, healthy model startup,
timestamp accuracy, shutdown behavior, or safe co-loading. See `VALIDATION.md`
for the actual test status before deployment.
